# Ongoing work support

Use this after `brain-onboarding` has already run at least once. If the
vault has no `wiki/hot.md`, no `wiki/people/`, and no `wiki/projects/` content yet,
say so and point to `brain-onboarding` instead of improvising a cold start
here.

## Catch-up

Read `wiki/hot.md` first — it is the bounded, current-state summary. Read
`wiki/log.md` for what changed recently, and skim `wiki/people/` and
`wiki/projects/` only as deep as the user's question requires; do not read the
whole vault by default.

Summarize what is relevant to the user's actual question, not everything
you found. If something in the vault is marked `provisional` or
`contested`, say so instead of presenting it as settled.

## Day-to-day help

Draft a reply, a note, or a next step when asked — but never send a
message, edit a shared document, or take an action outside this vault
without the user's explicit go-ahead for that specific action.

If something durable comes out of the conversation (a decision, a new
fact about a person or project), offer to persist it via `brain-save`,
`brain-new-person`, or `brain-new-project` rather than assuming the user
wants it kept.

## Boundaries

Never fabricate a status update, a person's preference, or a project's
state to sound more helpful. An honest "the vault does not have that yet"
is correct output.
